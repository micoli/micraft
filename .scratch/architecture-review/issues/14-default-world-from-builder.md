## Agent Brief

**Category:** enhancement
**Summary:** Build the persistent default World with `buildGameWorld`, delete every per-World Koin provider, and
let each `GameWorld` build its own `CommandContext`.

**Current behavior:**
The default World is assembled by `GameLoop`'s constructor from a mix of Koin singletons (passed by `Application`)
and `GameLoop` defaults, then `GameWorld(...)` is called with ~45 arguments and callback lambdas into `GameLoop`.
A Koin `CommandContextModule` builds the default World's `CommandContext` from per-World singletons. Other Worlds
get a partial `copy`, which leaks the default World's `namedPoints` and `persistence`. `Application` also reads
per-World singletons directly (`QuestManager` for `QuestsController`, `SessionRegistry` for the player
armors/hands/owned controllers). There are two `RailNetworkRegistry` caches and an unused Koin `BlockInteractor`.

**Desired behavior:**
- The default World is `buildGameWorld(DEFAULT_ID, generator, shared, opts with persistence)`, and its behaviour
  is unchanged (guaranteed by the tests from [13](13-buildgameworld-matches-production.md)).
- Koin has no provider for a per-World subsystem (combat, spells, NPC subsystem, quests, trade, pets, claims, mail,
  auction, block break/place/interact, chat service, experience, stats, registries…). It keeps config, auth,
  persistence roots, `SharedGameServices` and loaders.
- Each `GameWorld` builds its own `CommandContext` with the same fields as today. `CommandContextModule` and the
  `copy`-with-overrides logic are gone.
- HTTP controllers that read a per-World subsystem go through `gameLoop.defaultWorld`. Behaviour is unchanged: they
  still target the default World only.
- One `RailNetworkRegistry` and one `BlockInteractor` per World.

**Key interfaces:**
- `GameWorld`: owns and exposes its subsystems and its `CommandContext`
- `GameLoop.defaultWorld`: the only path from process-level code to the default World's subsystems
- `GameLoop` may still take its current constructor for now (slimming is [15](15-gameloop-takes-built-world.md))

**Acceptance criteria:**
- [ ] No Koin definition returns a per-World subsystem type; `CommandContextModule` is deleted
- [ ] Every `buildGameWorld` behavioural test from 13 also passes against `GameLoop.defaultWorld` in a production
      boot configuration
- [ ] A command run in a Test world sees that World's named points, not the default World's
- [ ] `make dc CMD="./gradlew :server:test"` green, `make e2e` green, `make dev-restart-server` boots the default
      World without ERROR, and a player's state survives a restart

**Out of scope:**
- Resolving the target World from `X-Micraft-Game-Session` in those HTTP controllers (separate ticket if an E2E
  test needs it)
- Reshaping `CommandContext` ([10](10-command-context-deps.md))
- Removing `GameLoop` constructor defaults ([15](15-gameloop-takes-built-world.md))
