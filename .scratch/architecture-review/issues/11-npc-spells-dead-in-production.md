# Boss NPCs never cast their spells in the production world

Status: ready-for-agent
Strength: Strong

Split out of [04](04-gameworld-self-assembly.md) on 2026-09-28: found while verifying that ticket's premise, and it
is the defect that premise predicts. Fixing it does not need the refactor and must not wait for it.

## Files
- `game/GameLoop.kt`: the `GameWorld(...)` call (47 named arguments) omits `spellProcessor`
- `game/world/GameWorld.kt`: `val spellProcessor: SpellProcessor? = null`
- `game/world/GameWorldFactory.kt`: `buildGameWorld` does pass it
- `game/npc/NpcTickPipeline.kt`, `game/npc/NpcManager.kt` (`tickAggro`): forward it, then `spellProcessor?.tryNpcCast`
- `resources/entities/*/`: 10 NPC definitions ship a `spells:` block

## Problem
`GameWorld.spellProcessor` is nullable with a `null` default. The world built by `buildGameWorld` — E2E worlds and
the admin simulator — passes it. The production default world, built inline by `GameLoop`, does not. So in
production `spellProcessor` is null all the way down `fullSimulationTick` → `NpcTickPipeline.tick` →
`NpcManager.tickAggro` → `spellProcessor?.tryNpcCast(...)`, where the safe call swallows it without a log.

Every boss NPC carrying `spells:` — storm_roc, alpha_direwolf, ancient_treant, bog_hydra, crystal_golem, frost_wyrm,
kraken_spawn, magma_golem, pharaoh_wraith, plague_ogre — therefore never casts for a real player. Player spellcasting
is unaffected: `IntentCollector` receives the processor straight from `GameLoop`, not through `GameWorld`.

`SpellProcessorAoeTest` exercises `tryNpcCast` directly, so the unit test passes while the feature is dead.

## Agent Brief

**Category:** bug
**Summary:** The production world is built without a spell processor, so no NPC ever casts a Spell.

**Current behavior:**
A `GameWorld` may be constructed with no spell processor, and the production world is. NPC spellcasting is reached
through a safe call on that field during the NPC tick, so the omission is silent: no error, no log, no failing test.
NPCs defined with Spells behave as if they had none, but only in the world real players connect to.

**Desired behavior:**
Every `GameWorld` that runs an NPC tick has a spell processor, so an NPC defined with Spells casts them wherever it
lives. The omission stops being expressible: a world cannot be built without one and still tick NPCs.

**Key interfaces:**
- `GameWorld.spellProcessor`: today nullable with a default. Making it required is the change that prevents the
  defect recurring; if it must stay nullable for a construction-order reason, that reason belongs in a comment and
  the tick path must log loudly rather than skip silently.
- No protocol, config or persistence change.

**Acceptance criteria:**
- [ ] The production default world exposes a non-null spell processor.
- [ ] A test asserts this on the default world, and fails if the argument is dropped again.
- [ ] An NPC whose definition carries Spells casts in the production world under the same conditions it already
      casts in an E2E world.
- [ ] No other `GameWorld` construction site loses a subsystem it passes today.
- [ ] `make dc CMD="./gradlew :server:test"` is green and `make quick-code-standard` is clean.

**Out of scope:**
- The wiring duplication that allowed this — that is [04](04-gameworld-self-assembly.md).
- Any change to NPC spell balance, cooldowns or selection.
- The `AbilityGate` work in [03](03-ability-gate.md); the NPC cast path stays as it is.
