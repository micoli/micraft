# GameWorld builds its own subsystems

Status: resolved
Strength: Worth exploring

## Files
- `game/GameLoop.kt` (2235 LOC, ~80 ctor params, `GameWorld(...)` L680-730 with ~45 args)
- `di/GameLoopModule.kt` (801 LOC)
- `game/world/GameWorldFactory.kt` (`buildGameWorld` L103, `buildE2eGameWorld` L489)
- `game/world/GameWorld.kt` (616 LOC)

## Problem
This duplication has already cost a production defect: `GameLoop`'s `GameWorld(...)` call dropped `spellProcessor`,
so no NPC cast a Spell in the production world. Split out as [11](11-npc-spells-dead-in-production.md).

`CombatProcessor`, `SpellProcessor`, `NpcSubsystemFactory`, `BlockBreaker`, `ClaimManager`, `TradeManager` and `PetManager` are each constructed in 3 places.
Adding a manager means editing 3 wiring sites plus `CommandContext`. GameWorld calls back into GameLoop through lambdas
(`commandContextProvider`, `broadcastPlayerAdminSink`, `intentCollectorProvider`, `onCommand`). It has a wide interface and no depth of its own.

## Solution
GameWorld assembles its per-world subsystems from `SharedGameServices` + options (`buildGameWorld` is already close to this).
GameLoop keeps only connection handling and the registry. Related: E2E GameWorld refactor (A9.1+).

Also in scope: `ClaimRegistry.factionAlly` is a post-construction `var` defaulting to "never an ally", so a world
built without the wiring silently denies faction allies. Turning it into a constructor dependency needs the
construction order this ticket reworks. See [06](06-authorizer.md).

## Triage Notes (2026-09-28)

Enhancement. Split into [12](12-production-wiring-defects.md)–[16](16-claim-registry-faction-ally-ctor.md). Principle
recorded as [ADR-0012](../../../docs/adr/0012-one-builder-per-world.md).

**Verified:**
- `CombatProcessor`, `SpellProcessor`, `NpcSubsystemFactory`, `BlockBreaker`, `TradeManager` and `PetManager` are
  constructed in 3 sites: the Koin graph, the `GameLoop` defaults, and `buildGameWorld`. `ClaimManager` is
  constructed in 2.
- The production World mixes the Koin graph with `GameLoop` defaults (Faction, Guild, Group, Mail, ActionBlock,
  BlockInteractor, Rail…).
- Production defects found → [12](12-production-wiring-defects.md): no Faction friendly-fire block, `/rest` does not
  clear regen, two MailManagers (no quest credit on attachments), BlockBreaker ignores weapon/tool `/reload`.
  Latent: two `RailNetworkRegistry` caches and a dead Koin `BlockInteractor`.
- Divergences in `buildGameWorld`: persistence stops at `WorldState`; no auction; mail only when persistent; item
  consumption is a no-op; guild bank is lost on dissolution; default faction config; no NPC loot validation;
  `MICRAFT_NPC_SEED` ignored.
- Spell, Pet, Chat, CharacterStats, StatusEffect, Movement, ChunkStreamer, Weather, Liquid, Vehicle, Siege, Group and
  MiniGame wiring is identical at all three sites.

**Decisions:**
- Q1: every World, the persistent default one included, comes from `buildGameWorld`.
- Q2/Q10: the production defects are fixed immediately in Koin (12), without waiting for the refactor.
- Q3: Koin keeps only process-level services; no `@Single` per World; `Application` goes through `defaultWorld`.
- Q4: 04 goes before [10](10-command-context-deps.md).
- Q5: `factionAlly` is in scope (16).
- Q6: `GameLoop(defaultWorld, process-level deps)` plus a single test helper (15).
- Q7: `persistence` is the one switch between persistent and memory-only.
- Q8: split into 13 (align) → 14 (production goes through the builder) → 15 (GameLoop slimmed) / 16 (factionAlly).
- Q11: when sites diverge, production wins; only persistence and the explicit options vary.
- Q12: the factions config goes into `SharedGameServices`; reload reaches every World.
- Q13: Mail always exists (in memory if not persistent); Auction only in a persistent World.
- Q14: each GameWorld builds its own `CommandContext` in 14; `CommandContextModule` and the `copy` logic are
  deleted.
- Q15: HTTP controllers go through `defaultWorld` (resolving the World from `X-Micraft-Game-Session` comes later if
  needed).
- Q16: one behavioural test per hook on `buildGameWorld`, written in 13.
