## Agent Brief

**Category:** bug
**Summary:** Fix four production-only wiring defects in the Koin graph: Faction friendly fire, `/rest` regen reset,
duplicated MailManager, and stale weapon/tool registries in BlockBreaker.

**Current behavior:**
The production World is wired by the Koin graph plus some `GameLoop` constructor defaults. Tests use the constructor
defaults, so they pass while production behaves differently:
1. **Faction friendly fire is not blocked.** `CombatProcessor` only applies the same-Faction friendly-fire rule when
   it has a `FactionManager`, and the Koin provider does not give it one. Two members of one Faction can damage each
   other in production even when the Faction config disables friendly fire. (`CONTEXT.md`: a Faction "disables
   friendly fire".)
2. **`/rest` does not clear regen accumulators.** The Koin-built `CommandContext` leaves `clearAccumulators` null.
   The `GameLoop` default wires it to `RegenProcessor.clearAccumulators`.
3. **Two `MailManager` instances over the same players directory.** The one players use (client mail,
   `PlayersController`) has no `QuestManager`, so claiming a mail attachment gives no quest credit. The Koin
   `OptionalMailManager`, which does have one, only feeds `AuctionManager`, so sale/expiry mails go through a
   different instance from the one the player reads.
4. **BlockBreaker does not see `/reload` of weapons and tools.** Koin gives it a snapshot of bare `Map` beans. The
   `GameLoop` default reads the live `EquipmentCatalog`.

**Desired behavior:**
1. Same-Faction attacks follow the Faction friendly-fire setting in the production World.
2. `/rest` clears the Character's regen accumulators in the production World.
3. The production World has exactly one `MailManager`. It has the `QuestManager`, and both client mail and the
   `AuctionManager` use it.
4. After a weapon/tool `/reload`, block breaking uses the reloaded definitions.

**Key interfaces:**
- The Koin providers for `CombatProcessor`, `CommandContext`, `OptionalMailManager` / `AuctionManager` and
  `BlockBreaker`
- `GameLoop` must use the Koin `MailManager` rather than building its own (inject it through the constructor as the
  other subsystems are)
- `BlockBreaker`'s weapon/tool registry lambdas should read `EquipmentCatalog`, not an erased `Map` bean

**Acceptance criteria:**
- [ ] A test built from the production Koin graph (not the `GameLoop` defaults) shows a same-Faction attack blocked
      when friendly fire is disabled
- [ ] A test through the production graph shows `/rest` clears regen accumulators
- [ ] A test shows claiming a mail attachment credits an item-collection quest objective, and that the auction's
      mail and the player's mailbox are the same instance
- [ ] A test shows block breaking picks up a reloaded tool definition
- [ ] `make dc CMD="./gradlew :server:test"` green; `make dev-restart-server` boots without ERROR
